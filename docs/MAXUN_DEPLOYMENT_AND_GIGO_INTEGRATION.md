# GiGo + Maxun self-hosted collection integration

## Decision

GiGo uses the open-source, self-hosted Maxun service as its general web collection engine. GiGo remains the business/research control plane: it decides what to collect, starts approved robot runs, retrieves results, and later turns permitted collected material into traceable research evidence.

Maxun is a separate service. It is not hosted by the GiGo Cloudflare Worker, and the integration must not be described as operational until a real Maxun instance is deployed and its API connection passes the Research page health check.

## What is implemented in GiGo

- Server-side Maxun API client in `src/integrations/maxun.ts`.
- Authenticated endpoints:
  - `GET /api/v1/integrations/maxun/status`
  - `GET /api/v1/integrations/maxun/robots`
  - `POST /api/v1/integrations/maxun/robots/{robotId}/runs`
  - `GET /api/v1/integrations/maxun/robots/{robotId}/runs/{runId}`
- Research page panel showing connection state, available robots and a button to start a robot.
- Maxun API key stays server-side in Cloudflare Worker secrets; it is never returned to the browser.
- Requests are owner-authenticated, HTTPS-only except localhost development, restricted to the documented self-hosted API paths, and bounded by a response-size and timeout limit.

The current UI can list and start robots that have already been created in Maxun's dashboard. It does not yet create Maxun robots through the self-hosted API, ingest run results into Supabase, or schedule Maxun robots from GiGo.

## Self-hosted API contract

The self-hosted API base is the Maxun backend URL plus `/api`, and it authenticates with `x-api-key`. The implemented integration uses the self-hosted API, not Maxun Cloud's `/api/v1` endpoints or its paid credit system.

Official documentation:
- API authentication and base URL: https://docs.maxun.dev/api/api
- Self-hosted API endpoints: https://docs.maxun.dev/api/open-source-api
- Docker installation: https://docs.maxun.dev/installation/docker

## Deployment reality and zero-budget constraint

Maxun's official Docker Compose installation runs multiple services: PostgreSQL, MinIO, Redis, backend, frontend and a browser service. The browser automation component needs substantial memory and shared memory. This is not a workload that can run inside a Cloudflare Worker, Supabase Edge Function, or a typical small free serverless function.

A free source-code licence does not mean free 24/7 hosting. Free application hosts commonly sleep, have ephemeral storage, or do not support the browser/container resources and persistent volumes Maxun needs. Do not deploy this stack to a provider until persistent storage, browser support, memory, networking, and ongoing price are verified.

Practical first deployment options:
1. A Windows/Linux computer with Docker Desktop/Engine for a local proof of concept. GiGo can reach it only while it is online and exposed through a secure HTTPS tunnel or reverse proxy.
2. A suitable always-on server that the owner already has access to.
3. A genuinely free cloud host only if its current terms and resource limits demonstrably support the full multi-container stack and persistent data. Do not assume a trial is permanently free.

For a temporary local test, a secure temporary tunnel can expose the Maxun backend to the GiGo Worker. Do not expose the database, MinIO, Redis, browser control port or Docker daemon to the public internet. Do not use a temporary tunnel URL for production scheduling.

## Deployment configuration

After Maxun is deployed and its backend is reachable over HTTPS, add these as Cloudflare Worker secrets for `gigo-api`:

- `MAXUN_BASE_URL`: the backend origin/base path, for example `https://scraper.example.com` (do not append `/api`).
- `MAXUN_API_KEY`: the API key generated by the self-hosted Maxun dashboard.

Never put these values in `wrangler.toml`, source code, the browser, screenshots, or chat. The Research page connection state should then change from “not connected” to “connected”.

## Security and platform scope

Maxun is a general web collection/crawling tool, not a guarantee of unrestricted social-platform access. It must not be configured to bypass logins, private-account controls, CAPTCHAs, rate limits, paywalls or platform anti-bot measures. For Instagram, TikTok, Facebook, YouTube, X and LinkedIn, GiGo must respect each platform's terms, official API permissions and applicable law. A public URL being visible in a browser does not automatically make automated collection permitted.

2. Create a small test robot in the Maxun dashboard against a permitted public test website.
3. Start it from GiGo and retrieve its completed run data through the integration.
4. Normalize and save allowed results into the selected GiGo research brief, preserving original URL, platform/source, collection time and unreviewed evidence status.
5. Add durable job orchestration, run polling/webhooks, retries, quotas and cancellation.
6. Add reusable collection templates and platform-specific connectors only after access rules and test coverage are established.

The GiGo API and Research page integration scaffolding are committed. Maxun itself has not been deployed or connected. No social-platform robot has been created or tested, and no Maxun-collected data has yet been saved into Supabase.
